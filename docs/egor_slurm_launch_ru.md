# Egor v2: запуск на кластере

Одна траектория — одно независимое задание планировщика. MANIA не выбирает
узлы и не отправляет `sbatch`; MPI и распределения одной траектории по узлам нет.
Работайте из checkout `egor-production-v2`, установленного в активной среде.

## Один раз: подтверждение исходных файлов

Интерактивно или внутри выделенной allocation:

```bash
conda activate mania-egor
cd ~/MANIA_WANIA
./init_egor_production.sh /path/to/Egor /path/to/results
```

Инициализация проверяет **все девять** наборов и показывает точные соответствия
DCD / PSF / CONF / OUT / XSC. Введите имя проверившего, примечание и `y`.
Область подтверждения — только `source_run_correspondence_only`: не PBC,
подготовленные координаты, контакты или QC. Пустой ответ/`N` не создаёт
подтверждения. Инициализация не готовит DCD и не запускает расчёт.

При неизменных байтах повторная инициализация проверяет и использует сохранённое
подтверждение без вопросов. Изменённое или повреждённое подтверждение не
перезаписывается. Рабочие задания требуют завершённой инициализации и никогда
не запрашивают согласие. Технический флаг `--TEST-0ss-r1-5-8ns` предназначен только
для разработчика: его отдельное пространство не заменяет нормальную инициализацию.

## Выбор расчёта

Одна траектория:

```bash
./run_egor_one.sh /path/to/Egor /path/to/results namd_egor_wt_0ss_r1
```

Одна реплика во всех трёх состояниях:

```bash
./run_egor_replica.sh /path/to/Egor /path/to/results r1
```

`run_egor_replica.sh` обрабатывает три траектории **последовательно внутри одного
задания**. Допустимы только `r1`, `r2`, `r3`. Все девять последовательно:

```bash
./run_egor_all.sh /path/to/Egor /path/to/results
```

Допустимые ID: `namd_egor_wt_0ss_r1`, `namd_egor_wt_0ss_r2`,
`namd_egor_wt_0ss_r3`, `namd_egor_wt_1ss_r1`, `namd_egor_wt_1ss_r2`,
`namd_egor_wt_1ss_r3`, `namd_egor_wt_2ss_r1`, `namd_egor_wt_2ss_r2`,
`namd_egor_wt_2ss_r3`.

## Независимые задания SLURM

Для параллельного выполнения на узлах отправьте отдельные задания:

- job1 → `namd_egor_wt_0ss_r1`;
- job2 → `namd_egor_wt_1ss_r1`;
- job3 → `namd_egor_wt_2ss_r1`;

либо девять независимых заданий для всех ID. Во всех заданиях укажите одинаковые
корни входов и результатов. Планировщик решает, где и когда они выполняются.
Ресурсы задавайте по правилам своего кластера. Минимальное тело личного sbatch:

```bash
#!/usr/bin/env bash
set -euo pipefail
source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda activate mania-egor

"$HOME/MANIA_WANIA/run_egor_one.sh" \
    /path/to/Egor \
    /path/to/results \
    "$TRAJECTORY_ID"
```

Задайте `TRAJECTORY_ID` для каждого задания. Личные sbatch-скрипты можно хранить
в `~/MD_workflow/Scripts_for_cluster` и вызывать launcher абсолютным путём.
Известная рабочая среда Егора: `mania-egor`, Python 3.12.14,
`mania-wania 0.1.0`, MDAnalysis 2.10.0; `pip check` — no broken requirements.

## Повтор и ограничения

Инициализация имеет отдельную кратковременную блокировку. Каждый ID имеет свою
блокировку на всё время подготовки/расчёта; второй запуск того же ID отклоняется.
Разные ID могут выполняться одновременно. Файловая система общих результатов
должна поддерживать согласованные между узлами POSIX `flock`; проверьте это
с администратором. Файлы блокировок не удаляйте, в том числе после сбоя.

Входы должны допускать запись и жёсткие ссылки: `.mania_egor/` хранит общую
копию authority и отдельные подготовленные данные каждой траектории. Не меняйте
исходные файлы или общие служебные файлы после инициализации. Рабочее задание
проверяет текущие байты выбранного набора и соответствие жёстких ссылок, поэтому
старый снимок не скроет замену исходного файла. Корни входов и результатов
не должны содержать друг друга. Оценка свободного места не резервирует диск;
при параллельном запуске учитывайте суммарный объём всех подготовленных DCD
и результатов. Поддерживайте стабильное UTC/NTP.

Завершённый результат строго проверяется и возвращает `reused=true`. Неполная
попытка сохраняется, следующий запуск получает новый номер; продолжения
контактов с середины нет. После аварийного завершения launcher убедитесь, что
его вычислительный дочерний процесс завершился: он тоже удерживает блокировку.
`science_complete` не означает финальные QC, агрегацию или публикацию.
