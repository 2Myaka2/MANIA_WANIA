## Development order vs production DAG

Development order was `27 -> 28 -> 29 -> 30 -> 31 -> 32 -> 33`: the aggregation
engine had to exist before the QC-to-aggregation bridge could be implemented.
Production execution order differs from development order. The Dataset production
DAG, identified by `mania.dataset_production.v1.0`, is:

```text
27–30 per-replica scientific outputs
  -> 32 QC and authoritative DatasetQCDecisionSet
  -> accepted QC-derived Stage 31 aggregation manifest
  -> 31 replica aggregation using that manifest
  -> 33 publication export
```

`PRODUCTION_EXECUTION_DAG` exposes these five ordered nodes deterministically.
The shorthand is `27–30 -> 32 -> 31 -> 33`, with the QC-derived control bridge
between decisions and aggregation. Production aggregation must never be placed
before QC merely because its development stage number is smaller.

## Keys, logical types and descriptor validation

The four column types are `string`, `integer`, `number`, `boolean`. Nullability
is separate; neither CSV types nor Arrow types define science. Frozen
`PublicationColumnSpec`, `PublicationForeignKeySpec`, `PublicationTableSpec`,
`PublicationJSONSpec`, `PublicationArtifactSpec` and `PublicationArtifactRegistry`
use immutable tuple members. Their `to_dict()` results are independent JSON-safe
values. Identical contracts have byte-identical `json.dumps(..., allow_nan=False)`
representations with the same serialization options, without timestamps, UUIDs
or environment-derived values.

All tables declare nonnullable primary keys. Descriptors reject duplicate/empty
column names, invalid types, duplicate/absent/nullable PK columns, duplicate FKs,
absent FK columns, duplicate table/artifact IDs and paths, and nonportable paths.
The registry also checks FK target existence, target primary keys and matching
logical column types. Actual row uniqueness, canonical values, population rules
and cross-table consistency are enforced later in 33.B–D.

Abbreviations below are exact ordered keys:

| Key | Columns |
| --- | --- |
| System | `dataset_id, system_id` |
| Replica | `dataset_id, system_id, trajectory_id, replica_id` |
| Window | Replica + `window_id, window_index` |
| Canonical node | `canonical_reference_id, canonical_residue_number` |

`condition` never participates in a PK or replica join. Bare `replica_id` is
never globally authoritative. A Window key binds one exact physical definition;
conflicting definitions for the same key must fail future row validation.
Window ID alone cannot establish physical compatibility.

Foreign keys connect simulations to systems and their one-to-one QC decision,
time windows to simulations, QC to simulations, findings to decisions and evidence
to findings. Annotations reference systems and nodes. Each per-replica scientific
table references simulations, time windows and its canonical endpoint node(s).
Aggregates reference systems and canonical node(s). Metrics reference simulations
and, when present, a full Window key. Their `window_id` and `window_index` must
both be null for non-window metrics, or both present and resolve to a Window row;
partial nulls are invalid. The simulations/QC reference cycle declares complete
one-to-one linkage, not CSV loading order.

## Excluded trajectories remain part of Dataset history

Historical/provenance population differs from scientific release population.
Every production candidate replica, including QC-excluded and technically
unavailable candidates, remains in simulations metadata, normalized QC tables
and provenance. Full identity, QC status, release decision, reason and structured
evidence linkage remain available. PASS findings also remain auditable.

A replica with `qc_status=fail` and `release_decision=excluded` still has its
simulations row and decision explanation, with both publication inclusion
booleans false. It never enters a scientific aggregate denominator. Its absence
from scientific tables is explained by authoritative QC rather than erased from
Dataset history. This preserves historical visibility and prevents survivorship
bias in Dataset documentation.

`included_in_replica_aggregation=true` requires an actual final QC-derived
Stage 31 member state of `available`. QC-excluded and technically unavailable
members are false. `included_in_scientific_release=true` requires both
`release_decision=available` and the required accepted per-replica scientific
evidence for the publication layer. A missing technical artifact is not QC
exclusion. Pending review grants no scientific release eligibility.

Simulations has one row per replica, whereas evidence and aggregation availability
can vary by layer/window. Its booleans summarize actual eligible contributions
(at least one eligible contribution is necessary for true), and never authorize
another layer/window. The later exporter derives them from accepted authority;
33.D checks each scientific row/member separately. Availability status/reason
must remain traceable to final QC-derived member evidence; an absent final state
stays null. No synthetic availability or exclusion may be invented to fill a cell.

## Metadata schemas

### Systems and simulations

`systems` has one row per Dataset system, independently of replica count, with
System PK and `engine, variant_id, condition, disulfide_state`. Engine/variant
identity is required; `condition` and `disulfide_state` retain accepted nullability.
Concrete NAMD condition labels remain unresolved and must not be invented.
Systems sharing a condition remain distinct.

`simulations` has one row for **every production candidate replica**, with Replica
PK, the same system metadata, and:

- `qc_status, release_decision, decision_mode, decision_reason_code,
  human_readable_reason`;
- `aggregation_availability_status, aggregation_availability_reason`;
- `included_in_scientific_release, included_in_replica_aggregation`.

PASS decision reasons remain null as accepted by Stage 32. Availability reason
is nullable according to upstream evidence. Inclusion booleans follow the
population rules above; they are not manual overrides of QC.

### Time windows

`time_windows` uses Window PK and carries:

- requested production: `requested_production_start_ns, requested_production_end_ns`;
- requested window: `requested_window_start_ns, requested_window_end_ns,
  right_endpoint_inclusive`;
- schedule: `window_length_ns, window_step_ns, overlap_percent, frame_stride_ps`;
- evidence: `expected_sample_count, resolved_sample_count, missing_sample_count,
  coverage_fraction`;
- observed endpoints: nullable `effective_start_ns, effective_end_ns`.

Expected/resolved counts copy accepted requested/resolved sampling evidence.
Requested scientific boundaries and effective observed coverage must never
collapse into one start/end pair. Missing requested samples are not negative
observations and never enter the resolved-frame occupancy denominator.

### Contact definitions

`contact_definitions` is explicitly parameterized long form: one row per parameter
tree node, keyed by Replica + `contact_definition_id, parameter_path`.
Each definition binds an authoritative per-replica contact layer and interaction
type. Columns include `contact_layer, interaction_type, parameter_kind,
string_value, integer_value, number_value, boolean_value, unit,
source_artifact_role, source_artifact_path`.

Layers distinguish `protein-protein`, `protein-lipid`, `protein-glycan`. Required
parameter roots are exposed by `CONTACT_DEFINITION_REQUIRED_PARAMETERS`:

```text
atom_selections
distance_definition
cutoff
type_specific_parameters
pbc_correction_status
occupancy_denominator_semantics
episode_continuity_semantics
gap_tolerance
lifetime_semantics
specialized_distance_semantics
```

The root path is `$`; child names append `/` and escape `~` as `~0`, `/` as `~1`.
Array children use contiguous zero-based decimal indexes. `parameter_kind` is
`string`, `integer`, `number`, `boolean`, `null`, `object` or `array`. Scalar nodes
populate exactly their corresponding typed value field; container/null nodes
populate none. Explicit object/array nodes preserve empty containers and the
distinction between lists and mappings. A string-kind blank `string_value`
represents an actual empty string; null-kind represents logical absence. This
explicit discriminator prevents CSV ambiguity without using a null sentinel.
Container order is not scientific; array order and all scalar values are retained.
These parameter rows remain scalar logical columns, with no JSON/Arrow column type.

Required roots preserve complete accepted definitions, using null for a parameter
that is explicitly inapplicable. `cutoff` includes value, unit and comparison
operator(s), not a guessed globally inclusive flag. Atom selections include
the authoritative runtime selection/filter and all applicable named atom sets.
`type_specific_parameters` retains accepted detection options, atom maps,
angle/range rules, backbone adjacency/priority, exclusions and geometry parameters.
No accepted parameter may be replaced by a single generic distance cutoff.

The inspected accepted implementation requires at least these distinctions:

| Definition | Accepted evidence to preserve |
| --- | --- |
| Generic residue contact | Actual `PreprocessingContactDetectionOptions`, including cutoff, unit, atom filter, selection, same-residue/duplicate exclusions and skip lists. |
| Backbone | Accepted adjacency/priority rules, CA atom definition, inclusive 4.5 Å maximum. |
| Hydrogen bond | Donor/acceptor/hydrogen rules, donor–acceptor distance ≤3.5 Å and D–H–A angle ≥120°. |
| Disulfide | SG atom selection and distance ≤2.2 Å. |
| van der Waals | Heavy-atom distance interval 3.0–4.5 Å inclusive at both ends. |
| Hydrophobic | Accepted residue set and CB–CB distance ≤5.0 Å. |
| Ionic / salt bridge | Their distinct accepted charged-atom maps and maxima ≤6.0 / ≤4.0 Å. |
| Aromatic π | Ring atom sets/geometry, centroid distance ≤7.0 Å, sign-invariant normal angle, parallel `<30°` and T-shaped inclusive `60°..120°` rules. |
| Cation–π | Cation-center/ring definitions and **strict** distance `<6.0 Å`. |
| Protein-lipid | Whole supplied partner heavy-atom minimum, inclusive 6.0 Å. |
| Protein-glycan | Whole supplied partner heavy-atom minimum, inclusive 4.5 Å, carrier-summary exclusion/linkage semantics. |

Authority is the accepted [contact implementation](../src/mania/preprocessing/trajectory_contacts.py),
[typed chemistry](../src/mania/preprocessing/trajectory_contact_chemistry.py),
[geometry](../src/mania/preprocessing/trajectory_interaction_geometry.py), and
[Stage 29 lipid](protein_lipid_contact_contract.md)/[glycan](protein_glycan_contact_contract.md)
contracts. These are documentation of existing parameters, not new detectors or
new residue lists. Later adapters must copy actual supported configuration and
constants from accepted evidence; 33.A does not execute the contact code.

Shared semantic parameter values preserve: no internal minimum-image/PBC
correction; resolved-frame occupancy denominator; continuity through consecutive
requested sample indexes within one replica/window; missingness and negative
observations break episodes; gap tolerance is zero; lifetime is actual last minus
first positive time in ns (a singleton has zero duration). Specialized mean/min
distance is over positive frames only. External PBC preparation is not inferred
from a passed technical audit and the scientific PBC protocol remains unresolved.

### Software versions

`software_versions` is keyed by
`dataset_id, source_artifact_path, component_role, component_name`. It carries
nullable `version, run_id` and required `source_artifact_role`.
Rows bind components to authoritative software identity/runtime/engine evidence,
allowing different source runs to report different versions. Roles distinguish
MANIA/WANIA package, Python/runtime packages and MD-engine software. Accepted
sources include package `SoftwareIdentity.version` and runtime Python, NumPy,
MDAnalysis, Pydantic and PyYAML version metadata. Engine versions require supplied
authoritative evidence. An unknown version is null (or no component row when no
component evidence exists), never guessed from engine name, paths or host state.

## Aggregates and publication authority

Every aggregate requires lineage proving:

1. an authoritative Stage 32 `DatasetQCDecisionSet`;
2. an accepted QC-derived Stage 31 manifest generated from those decisions;
3. the actual Stage 31 aggregation run produced using that manifest.

The accepted manifest is `replica_aggregation_manifest_qc_derived.json` or the
equivalent accepted QC-derived model. A schema-correct pre-QC Stage 31 aggregate
may be a technically valid engine test/intermediate run, but is **not
publication-authoritative**. 33.D must enforce the connected lineage, not merely
the presence of three unrelated references. It must also retain excluded replica
history even when no scientific row survives for that replica.

All three tables preserve Stage 31 system/engine/variant/condition/disulfide
metadata and the entire requested physical window definition: ID/index,
production bounds, window bounds, right inclusion, length, step and overlap.
Their PK is System + engine + all those window-definition columns + reference ID
+ the entity key. There is no trajectory/replica identity in aggregate rows.
System identity fixes labels independently of replica count or condition equality.

Protein entity fields are canonical source/target numbers and names plus
`edge_type`; its entity key is the two numbers and edge type. Specialized entity
fields are canonical protein number/name, `partner_correspondence_id, partner_name`;
its entity key is the canonical number and correspondence ID. Each table preserves
exactly the six accepted occupancy/support statistics:

```text
mean_occupancy
std_occupancy
median_occupancy
n_replicates_available
n_replicates_supporting
support_fraction
```

Sample SD remains null for fewer than two available replicas. No new aggregate
distance, lifetime, contact-frame total or specialized edge weight is introduced.
**`partner_correspondence_id` is an aggregation correspondence identifier; it is
not a canonical lipid/glycan identity, chemical registry identifier or cross-system
molecule identity.** Specialized aggregation requires accepted explicit partner
correspondence for available members. Stage 33 never infers correspondence.

## Metrics

`metrics` is long form, with Replica identity, deterministic `metric_id`, nullable
`window_id, window_index`, explicit `metric_name`, numeric `metric_value`, nullable
`unit`, and `source_artifact_role, source_artifact_path, source_record_key`.
The PK is Replica + `metric_id`, so nullable window identity never becomes a PK.
`metric_value` may be null only if the accepted source metric is explicitly null.
No closed metric vocabulary is invented and no metric is recomputed.

`source_record_key` is the deterministic accepted source-row/record locator,
including its window identity when applicable. The future adapter forms
`metric_id` by concatenating four length-prefixed UTF-8 components in this order:
source role, source path, source record key, metric name. Each component is its
decimal UTF-8 byte length, `:`, then its exact text. This reversible key uses no
UUID, clock, nullable sentinel or publication row-order dependency.
Distinct source evidence can represent the same named metric without collision.
Excluded-replica QC/review metrics stay in QC evidence/provenance, rather than
being silently promoted into main scientific metrics.

## Format policy and losslessness

The logical publication model is authoritative. CSV is the mandatory normative
encoding for all 17 tables; JSON is mandatory for the three hierarchical release
artifacts. Parquet is **optional**, a serialization adapter over the same validated
logical tables. It is neither normative science nor required by MANIA core.

CSV must work without a Parquet backend. An explicitly requested Parquet export
without a backend must fail with a clear deterministic optional-adapter error.
A future narrow optional Arrow-capable export dependency such as pyarrow is
preferred over adding pandas merely for serialization. No pandas, pyarrow,
fastparquet or other dependency is added now; MANIA imports never require them.
CSV and optional Parquet must reconstruct equal logical models, with no
independent scientific transformation in Parquet.

Logical null is `None`/absent logical value: future CSV blank cell, JSON `null`,
Parquet native null. Literal strings `None`, `null`, `NA`, `N/A` are not null
sentinels. Accepted nullable text is nonempty when present; the typed contact
parameter discriminator separately preserves actual empty-string values.
CSV boolean spelling is stable lowercase `true`/`false`, never `0/1` or `yes/no`.
Finite numbers round-trip without publication-layer rounding of occupancy,
support, lifetime, distance, mean, median, SD or coverage. Formatting may encode
an accepted value but cannot change it. Nonfinite values cannot be serialized
as valid scientific numbers.

Serializers must not recalculate occupancy/lifetime/statistics, change nulls,
derive canonical IDs from source IDs, reevaluate hard/review QC or manual decisions,
or alter inclusion/exclusion. No publication schema grants a QC override.

## Verification boundary

The release contract tests check immutable/invalid descriptors, exact paths,
keys/references, canonical identity, accepted Stage 30/31 scalar projections,
QC history/normalization, deterministic serialization, format/dependency policy
and an import/operation smoke with external capabilities blocked. Stage 27–32
regressions and full repository checks protect accepted science. Wheel verification
uses an offline build and an installation outside the checkout. No test in 33.A
generates publication data or substitutes synthetic evidence for Stage 34.
